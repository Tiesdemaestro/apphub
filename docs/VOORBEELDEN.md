Kies **Project toevoegen**, plak een link, kies **Project bekijken**, bevestig je toestemming en kies **Toevoegen → Openen**.

Deze links werken zodra de bijbehorende GitHub Pages-publicatie is geslaagd. Er is geen nieuwe iPhone-build nodig voor het toevoegen van deze webprojecten.

## Een korte test

1. Voeg een project toe en maak zelf één item aan.
2. Bewerk het item en probeer de statusknop of dagknop.
3. Ga terug naar AppHub en open het project opnieuw, binnen dezelfde sessie.
4. Maak via **Gegevens en back-up** een kopie en bewaar de tekst buiten de simulator.
5. Verwijder het item en herstel de back-up. Plak ook eens ongeldige tekst: de bestaande gegevens moeten behouden blijven.

Er wordt geen voorbeeldinhoud tussen je eigen gegevens gezet. Alle projecten gebruiken lokale IndexedDB-opslag met aparte databasenamen. GitHub Pages-projecten op hetzelfde domein zijn geen beveiligingsgrens. Een nieuwe Appetize-sessie kan je opslag wissen; neem een back-up mee.

## Grenzen

- Geen automatische cloudsynchronisatie, accounts, AI-dienst of meldingen op de achtergrond.
- GitHub-repository’s moeten een geschikt manifest én gepubliceerde websoftware aanbieden. Een willekeurige repository draait niet automatisch.
- Technische controles zijn geen Apple-goedkeuring. De hoofdapp en de voorbeelden moeten nog op een fysiek toestel worden getest.
- De voorbeelden verwijzen voor technische hulp naar de GitHub-projectpagina. Definitieve uitgeversgegevens en de overige hostverplichtingen blijven onderdeel van het App Store-traject.
